Instructor FAQ

The questions that actually come up when running Orbit Academy. For the full narrative version — course structure, teaching notes, module-by-module beats — see the Instructor's Guide.

Accounts & roles

The hub shows me as a student. How do I fix that?

Almost always this means someone registered before you did — usually a test account made while setting the server up. Only the very first account created becomes the instructor.

Fix it from a terminal in the course folder. First see where things stand:

node tools/set-role.js

That lists every account, oldest first, with a ★ next to each instructor. Then promote yourself:

node tools/set-role.js you@example.org instructor
Stop the server first. The server keeps the whole database in memory and rewrites the file every time a student saves progress, so a change made underneath a running server gets silently undone. Close the launcher window (or press Ctrl-C), run the command, then start it again. Log out and back in to see the change.

The same command demotes an account by passing student instead. It refuses to remove the last instructor, since that would leave nobody able to reach the roster or the editor.

Having two or more instructors is perfectly fine — you do not need to demote the old test account, though it is tidy to do so once you have promoted yourself.

Who becomes the instructor?

The first account ever registered on that server, automatically. Everyone who registers afterwards is a student. So when you set up a new machine, register your own account before you let any students near it.

Is there a default instructor login I can use?

No, deliberately. No account or password ships with the course. A fixed credential in the repository would be the same on every installation everywhere, would stay in the project's history permanently, and is exactly the weakness security reviews look for.

Instead, a brand-new server tells you what is about to happen: its sign-in page says no accounts exist yet and that the account you create now becomes the instructor. So there is nothing to look up — just be first.

Why isn't there just a button to promote someone?

Deliberate. An endpoint that hands out instructor rights is the single most valuable target on this backend — it would grant the roster, every student's progress, and the worksheet editor. Role changes are therefore an offline, file-level operation. Anyone who can run set-role.js already has the data file in their hands, so it gives away nothing new.

How do I add or remove people?

Adding: students register themselves at the hub — send them the address and they create their own accounts. There is nothing for you to do.

Removing: use the delete button on that person's row in the Roster tab — see Deleting or resetting a student. Back up academy_data.json first; deletion cannot be undone.

Someone forgot their password.

Passwords are stored as salted scrypt hashes and cannot be recovered — by design, and there is no reset flow. The practical fix is to register a fresh account. If you need to preserve their progress, stop the server and copy the progress object from the old entry to the new one in academy_data.json.

Running it

What are the two ways to run this?

Both are fully supported, and the worksheets are completely interactive either way — quizzes score, feedback appears, tasks tick off, progress is saved. The only difference is where progress lives and whether there are accounts.

How do I run this for a room full of students?

Run the server on one machine and give students that machine's address instead of localhost — for example http://192.168.1.20:8080.

  • macOS: System Settings → Network → Wi-Fi → Details → TCP/IP → IP Address. Allow incoming connections for Node when asked.
  • Windows: Settings → Network & Internet → Wi-Fi → Properties → IPv4 address. Allow Node through the firewall on Private networks.

Register your instructor account before the students arrive, and leave the launcher window open — closing it stops the course for everybody.

How do I open the worksheet editor?

  1. Start the server and open http://localhost:8080.
  2. Sign in with your instructor account.
  3. Click ✏️ Edit worksheets on the hub — or go straight to editor.html.

It edits objectives, tutorial text, every exercise's teach/predict/do/observe/think blocks, quiz questions, options, correct answers and per-option feedback, and the final-check questions — from a form, with no code editing. Each save keeps a timestamped backup beside the file.

A student account is refused by the server, not merely by a hidden button, so this is the one thing that genuinely requires the instructor role. If you see a permission error, check the role question above.

Where is progress actually stored?

Server mode: academy_data.json in the course folder — accounts, salted password hashes and every task completion. That single file is your class records.

Bare mode: in the student's browser (localStorage), per browser and per machine. Clearing site data erases it, and it does not follow them to another computer.

Can I let a student skip ahead?

Prerequisite gating is enforced by the server, so there is no in-app override. Two options: have them work in bare mode (gallery.html), where every module is open; or stop the server and mark the prerequisite module complete in their progress entry in academy_data.json. The gallery is much the easier route for a one-off.

Can I delete a student, or reset their progress?

Yes — both are on the Roster tab of the instructor dashboard, one pair of buttons per row.

  • reset clears that student's progress but keeps their login, so they can start over with the same account.
  • delete removes the account and its progress permanently, and immediately invalidates any session they still have open.

Deleting asks you to type DELETE rather than just clicking OK — working down a roster of similar-looking rows is exactly where a misclick costs somebody's work.

Neither can be undone from the dashboard. Your copy of academy_data.json is the only way back, which is the practical argument for taking one before each cohort.

The server will refuse to let you delete your own account or the last remaining instructor — either would leave the course with nobody able to reach the roster or the editor.

Can I see which questions people got wrong?

Yes — the 📊 Where the class struggled tab on the instructor dashboard. Two views:

  • Questions the class got wrong most often, ranked, with how many students got each one right on the first try. This is the teaching signal: a task many students missed is usually a problem with the explanation, not the students.
  • Per student, a grid of modules with wrong-answer counts — so you can tell someone who is simply behind from someone who is struggling.

Note that every student eventually gets every answer right, because a wrong answer just asks again. So "passed" tells you little on its own; the wrong-answer count is what carries the information. A green cell means passed with no mistakes, amber means passed after struggling.

This only works in server mode — bare mode has nowhere to report to. It also only counts work done from this version onward; earlier progress has no wrong-answer history because the course never recorded it.

How do I start a fresh cohort on the same machine?

  1. Back up academy_data.json somewhere outside the course folder — that file is your record of the cohort that just finished.
  2. Either reset each returning student from the roster (keeps their logins), or delete the accounts and let the new group register themselves.
  3. Keep your own instructor account. If you delete everything and start over, remember the first account to register becomes the instructor — so register yourself first.

Offline & troubleshooting

Does this work on a machine with no internet?

Yes — that is the design target, and it is tested on every release. Everything the course needs is inside the folder, including the 3-D library and the planet maps. There is nothing to download at install time or at run time.

Copy the folder to the isolated machine and follow the normal instructions. To confirm the copy arrived intact:

bash tools/fetch-vendor.sh --check

The last line should read PASS — every vendored asset matches public/vendor/NOTICE.md. That file also records where every third-party file came from and under which license, if your accreditation process asks.

A simulator is blank, or says "3-D library not loaded".

This is never an internet problem — the library ships inside the folder. It means a file did not survive the copy or the unzip.

  • Windows: you probably missed the Unblock checkbox. Right-click the original ZIP → Properties → tick Unblock → OK, then extract again. This is the most common install failure by a wide margin.
  • Check that public/vendor/three.min.js exists and is about 600 KB.
  • Run bash tools/fetch-vendor.sh --check; in a git clone, git checkout -- public/vendor restores the originals.

Module 8's forward window shows plain spheres, not continents.

Expected in bare mode, and it says so on screen. Browsers refuse to let a page opened from disk read the pixels of a local image, and that window paints the planets by sampling the map. Run in server mode to get the mapped view. No instrument reading, number or physics result is affected.

What should I back up?

academy_data.json — that one file holds every account and all progress. The server keeps a .bak beside it, but that is not a backup strategy: copy it somewhere else before and after each cohort. It contains password hashes, so treat it as sensitive, and note that it is deliberately excluded from git for that reason.

Everything else in the folder is replaceable from the repository or the ZIP.
